Beyond the demo

A production agent isn't a function call.

Interruptible. Steerable. Observable.
The three things every "works on my laptop" agent is missing.

Everything you just watched

Five of the six verbs. One addressable thread.

sendMessage()paged the agent awake · steered it mid-run ("Berlin")
sendNotificationSignal()the second PagerDuty page — durable, deduped, mid-loop
queueMessage()the postmortem — waited its turn, fired itself
subscribeToThread()the second responder tab — N clients, one live stream
sendStateSignal()deploy-freeze policy riding a durable state lane
sendSignal()the low-level verb under all of it — processors can emit too

Routing is the runtime's job: wake / deliver / queue / persist — you just talk.
~200 lines of Signals wiring. Laptop tonight; multi-instance = same code + Redis pub/sub.

The whole trick

Two calls. That's the API.

// tap a coworker on the shoulder
agent.sendMessage(
  'Tickets are all from Berlin —' +
  ' focus the EU breakdown.',
  { resourceId, threadId },
)
// your webhook handler, verbatim
agent.sendNotificationSignal({
  source: 'pagerduty',
  priority: 'high',
  summary: 'pg at 4% errors',
  dedupeKey: 'pd:pg:err',
}, { resourceId, threadId })

Active run? Delivered into the loop. Idle thread? It wakes. For delivery, you don't have to care which — that's the whole bet.
