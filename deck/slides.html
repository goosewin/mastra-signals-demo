The default

Every agent you use has exactly one input.

The first message. After that it's a sealed box until it comes back.

You can watch it. You cannot talk to it.

Esc. Retype. Pay for the context again.

And production is rude

The world does not politely stop
while your agent runs.

  • A webhook fires 40 seconds in. CI goes red. A customer replies.
  • The user watches the stream and goes "no, not that".

Your three options today: kill and re-prompt · poll and cram it all into the first prompt · build your own message bus.

That's not an agent.
That's a batch job with good marketing.

The point

A production agent
isn't a function call.

It's a process you talk to.

Everything you just watched

Seven verbs, one addressable thread.

sendMessage()Wakes an idle thread, or lands inside a live run. You don't pick.
queueMessage()Waits its turn. Fires when the current turn ends.
sendNotificationSignal()Your webhook handler, verbatim. Durable inbox.
sendStateSignal()Named context lanes. Always fresh, never re-sent.
subscribeToThread()Any number of clients on one live stream.
sendToolApproval()The run parks on a tool call until someone decides.

Plus sendSignal() underneath them all. The wiring in tonight's demo is ~250 lines of TypeScript.

The two calls that did all of it
// someone in the room, typing on their phone,
// straight into a loop that is already running
await agent.sendMessage(
  'fix the pricing bug first — people are being overcharged',
  { resourceId, threadId },
)

// your webhook handler, verbatim
await agent.sendNotificationSignal({
  source: 'order-page-monitor',
  priority: 'high',
  summary: 'checkout errors spiking',
  dedupeKey: 'monitor:order-page:errors',
}, { resourceId, threadId })
